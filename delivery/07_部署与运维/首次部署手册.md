# 首次部署手册

## 适用场景

在一台全新服务器上用当前生产方式部署 EACY。当前生产方式是 Docker Compose：构建后端/前端镜像，启动 Redis、migration、API、Celery worker、Celery Beat、nginx。日常升级见 [[升级流程]]。

## 前置条件

- [ ] Linux 服务器已安装 Docker 与 Docker Compose v2
- [ ] 外部/远程 PostgreSQL `14+` 已创建库与账号，连接串可写入 `DATABASE_URL`
- [ ] OSS / TextIn / LLM / SMTP 等密钥已就绪
- [ ] 仓库代码已 `git clone` 到服务器，例如 `/data/eacy/eacy_project`
- [ ] 对外端口已放行，端口由 `.env.prod` 的 `HTTP_PORT` 决定

> [!warning] 当前 compose 不启动 PostgreSQL
> `docker-compose.prod.yml` 只管理 Redis 与应用容器。数据库必须是 `.env.prod` 中 `DATABASE_URL=postgresql+asyncpg://...` 指向的外部/远程 PostgreSQL。

## 执行步骤

### 1. 准备 `.env.prod`

```bash
cd /data/eacy/eacy_project
cp .env.prod.example .env.prod
```

逐项填写真实值，至少替换：

- `DATABASE_URL`
- `JWT_SECRET_KEY`
- `OSS_*`
- `TEXTIN_*`
- `OPENAI_API_KEY` / `OPENAI_API_BASE_URL` / `OPENAI_MODEL`
- `SMTP_*`（如启用注册/找回密码邮件）
- `HTTP_PORT`

所有变量含义见 [[环境变量清单]]。

### 2. 校验 compose 配置

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod config --services
```

预期服务：

```text
redis
migrate
api
worker-metadata
worker-ocr
celery-beat
nginx
worker-extraction
```

如果这里失败，先修 `.env.prod` 或 compose 配置，不要继续启动。

### 3. 构建镜像

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod build
```

镜像构建来源：

- 后端：`deploy/docker/backend.Dockerfile`
- 前端：`deploy/docker/frontend.Dockerfile`
- nginx 配置：`deploy/docker/nginx/eacy.conf`

### 4. 执行数据库迁移

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod run --rm migrate
```

迁移命令实际为 `alembic upgrade head`。首次部署必须确认数据库连接的是目标生产库。

> [!warning] migration 不会自动回滚业务数据
> 已有真实数据的库升级前必须先按 [[备份与恢复]] 做备份。

### 5. 启动应用

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d api celery-beat worker-ocr worker-metadata worker-extraction nginx
```

也可以在空环境中一次性构建并启动：

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
```

### 6. 验证健康

```bash
# 容器状态
docker compose -f docker-compose.prod.yml --env-file .env.prod ps

# 入口；端口替换为 .env.prod 的 HTTP_PORT，未设置时默认 80
curl -I http://127.0.0.1:${HTTP_PORT:-80}/

# API，经 nginx 反代
curl http://127.0.0.1:${HTTP_PORT:-80}/api/v1/auth/

# Celery worker 心跳
docker compose -f docker-compose.prod.yml --env-file .env.prod exec worker-ocr \
  celery -A app.workers.celery_app.celery_app inspect ping
```

Redis 队列长度：

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod exec redis redis-cli -n 11 llen ocr
docker compose -f docker-compose.prod.yml --env-file .env.prod exec redis redis-cli -n 11 llen metadata
docker compose -f docker-compose.prod.yml --env-file .env.prod exec redis redis-cli -n 11 llen extraction
```

## 验证方式

- [ ] `docker compose ... ps` 中 `api` healthy，worker 与 nginx running
- [ ] 浏览器打开站点，能登录
- [ ] 上传一份 PDF：状态依次走过“上传 → OCR → 元数据 → 归档”
- [ ] PDF 预览正常返回 `200 application/pdf`
- [ ] 新建/更新科研项目 CRF 时，抽取任务能入队并完成
- [ ] nginx/API/worker 日志无持续 5xx 或外部依赖鉴权错误

## 回滚方式

首次部署回滚 = 停止应用容器，保留外部数据库和 OSS 原件：

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod down
```

如果 migration 已写入错误 schema，按 [[备份与恢复]] 从部署前备份恢复数据库。不要在生产库盲跑 `alembic downgrade`。

> [!warning] 上线前最后检查
> - `ENABLE_AUTH=true`
> - `DEBUG=false`
> - `JWT_SECRET_KEY` 已替换为随机值
> - `.env.prod` 未提交 git
> - 种子账号 `admin@example.com` 等已修改密码或禁用
