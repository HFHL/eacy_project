# 升级流程

## 适用场景

线上 EACY 用当前 Docker Compose 生产方式升级到新版本：拉取代码、构建镜像、执行 migration、重启 API/worker/nginx。首次部署见 [[首次部署手册]]。

## 前置条件

- [ ] 已完成 [[备份与恢复]] 描述的数据库备份
- [ ] 已 review 本次升级 commit 范围，确认是否包含 Alembic migration（看 `backend/migrations/versions/` 新增文件）
- [ ] 已确认是否包含 env 新增字段（参考 [[环境变量清单]] 与 `.env.prod.example`）
- [ ] 已通知相关方升级窗口

## 执行步骤

### 1. 拉取代码

```bash
cd /data/eacy/eacy_project
git fetch --all
git status
git pull --rebase
```

> [!warning] 不要覆盖 `.env.prod`
> 新版本有新增 env 时，逐项 diff `.env.prod.example` 和 `.env.prod` 后手工补充。

### 2. 停止后台任务

先停 Celery Beat 与 worker，避免任务在 migration 中途读到不一致 schema。

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod stop celery-beat worker-ocr worker-metadata worker-extraction
```

如需观察队列堆积：

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod exec redis redis-cli -n 11 llen ocr
docker compose -f docker-compose.prod.yml --env-file .env.prod exec redis redis-cli -n 11 llen metadata
docker compose -f docker-compose.prod.yml --env-file .env.prod exec redis redis-cli -n 11 llen extraction
```

### 3. 构建镜像

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod build
```

只有依赖或前端资源变化时才会实际重建对应层；命令可安全重复执行。

### 4. 执行数据库迁移

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod run --rm migrate
```

> [!warning] migration 失败时
> 见 [[常见故障排查#migration失败回滚]]。不要在生产盲跑 `alembic downgrade`，多数 EACY migration 未实现安全 downgrade。

### 5. 重启 API

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d api
docker compose -f docker-compose.prod.yml --env-file .env.prod logs -f api
```

确认 API healthy 后再启动 worker。

### 6. 重启 worker、beat、nginx

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d celery-beat worker-ocr worker-metadata worker-extraction nginx
docker compose -f docker-compose.prod.yml --env-file .env.prod ps
```

变更只影响某类 worker 时，可单独重启：

- LLM 配置变更：`worker-metadata`、`worker-extraction`
- TextIn 配置变更：`worker-ocr`
- JWT/API 逻辑变更：`api`
- 前端构建变更：`nginx`

## 验证方式

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod ps
curl -I http://127.0.0.1:${HTTP_PORT:-80}/
curl http://127.0.0.1:${HTTP_PORT:-80}/api/v1/auth/
docker compose -f docker-compose.prod.yml --env-file .env.prod exec worker-extraction \
  celery -A app.workers.celery_app.celery_app inspect ping
```

- [ ] `api` healthy，worker 与 nginx running
- [ ] `migrate` 最近一次运行成功退出
- [ ] 上传 / 抽取一次小样本，全流程 OK
- [ ] 前端登录后 hard refresh，无 chunk hash 加载失败

## 回滚方式

### 代码/镜像回滚

```bash
cd /data/eacy/eacy_project
git log --oneline -5
git checkout <上一个稳定 commit>
docker compose -f docker-compose.prod.yml --env-file .env.prod build
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d api celery-beat worker-ocr worker-metadata worker-extraction nginx
```

### Migration 回滚

> [!warning] 优先从备份恢复
> 多数 EACY migration 是 forward-only。只有确认迁移脚本实现了安全 downgrade 时，才考虑手工 downgrade。

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod run --rm api \
  alembic downgrade <previous_revision>
```

### 完整恢复

需要恢复数据库时，先停业务：

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod stop api celery-beat worker-ocr worker-metadata worker-extraction
```

然后按 [[备份与恢复]] 从升级前备份恢复外部 PostgreSQL。
